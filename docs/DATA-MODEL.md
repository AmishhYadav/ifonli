# IfOnli data model

Source of truth: `src/server/db/schema/*.ts` (Drizzle). Migrations: `drizzle/` (`pnpm db:generate`, `pnpm db:migrate`). 47 tables in `public`. This page summarises purpose, key columns and constraints; plan section 6 is the design intent.

Conventions
- Primary keys are `uuid` (`gen_random_uuid()`), except Better Auth tables (text ids, generated by Better Auth), `settings` (natural key `key`), `states` (`code`), `pincodes` (`pincode`), `invoice_counters` (`financial_year`), `rate_limits` and the join tables `product_vibes`, `wishlist_items` (composite PKs).
- `created_at` / `updated_at` are `timestamptz` with `now()` defaults; `updated_at` is bumped by Drizzle `$onUpdate` (ORM updates only, there is no DB trigger). Append-only tables (`inventory_movements`, `order_events`, `admin_audit_log`, `policy_versions`, `wishlist_items`) only have `created_at`.
- Money is `bigint` in `*_paise` columns, mapped to JS `number` (safe to about 9e13 INR). Every money column has a `>= 0` CHECK (`> 0` for payment/refund amounts).
- Statuses are Postgres enums (`pgEnum`); see "Enum axes".

## Extensions and helpers (migration `0000_extensions.sql`)
`pg_trgm` and `unaccent` are installed in `public`, so plain Postgres (CI, `ifonli_test`) and Supabase behave identically. `public.immutable_unaccent(text)` wraps `unaccent()` (which is only STABLE) as IMMUTABLE so it can be used by the generated `products.search_tsv`. `citext` is not used (see coupons).

## Inventory (`inventory.ts`)
| Table | Purpose |
|---|---|
| `inventory_movements` | Append-only ledger. `delta <> 0`, `reason` (movement_reason), optional `order_id` and `actor_id`. Index (`variant_id`, `created_at`). |
| `stock_reservations` | Holds for prepaid checkouts: `qty > 0`, `expires_at`, `status`. Index (`variant_id`, `status`, `expires_at`). |

### Availability
```
available(variant) = variants.stock_on_hand
                   - COALESCE(SUM(qty) FILTER (WHERE status = 'active' AND expires_at > now()), 0)
```
```sql
SELECT v.id,
       v.stock_on_hand - COALESCE(SUM(r.qty), 0) AS available
FROM variants v
LEFT JOIN stock_reservations r
  ON r.variant_id = v.id AND r.status = 'active' AND r.expires_at > now()
WHERE v.id = ANY($1)
GROUP BY v.id;
```
Expiry is evaluated at read time, so correctness never depends on the release cron: an expired `active` row simply stops counting. When reserving, lock the variant rows first (`SELECT ... FOR UPDATE ... ORDER BY id`) and recompute availability inside the same transaction. A paid order flips its reservations to `converted` and decrements `stock_on_hand` with a `sale` movement; COD orders decrement directly with no reservation; cancel/expiry sets `released` (and `cancel_restock` for paid stock).

## Customers and carts (`customers.ts`, `cart.ts`)
- `customer_profiles` (1:1 with `user`, `phone`, `marketing_opt_in`, `deleted_at`). After account deletion it is a tombstone and the `user` row is anonymised (D-AUTH-3).
- `addresses` (per user; partial unique index allows one `is_default` per user).
- `wishlist_items` (PK `user_id`, `product_id`).
- `carts` (`token` unique = httpOnly cookie, `user_id` nullable, `coupon_code`, `version`, `expires_at`), `cart_items` (unique per cart+variant, `qty > 0`).

## Payments (`payments.ts`)
`payments` (`provider_order_id` unique, `provider_payment_id` unique and nullable, `amount_paise > 0`, `raw` jsonb), `refunds` (`payment_id` nullable for manual COD refunds, `provider_refund_id` unique nullable, `reference`), `webhook_events` (`provider_event_id` unique = idempotency, `processed_at`, `error`).

## Promotions (`promotions.ts`)
- `coupons`: `code` is plain `text` with a **unique index on `lower(code)`**, so `SAVE10` and `save10` collide. Chosen over `citext` to avoid another extension and keep the same behaviour on every Postgres; callers must compare with `lower(code) = lower($1)`. `value` unit depends on `kind` (percent = basis points 1..10000, fixed = paise > 0, free_shipping = 0; enforced by CHECK). `scope` jsonb `{vibes, types, products, excludeProducts}`, `stackable` (false in v1).
- `coupon_redemptions`: unique (`coupon_id`, `order_id`), status reserved/confirmed/released, indexes for usage counting by coupon and by `lower(email)`.

## Content (`content.ts`)
`banners`, `featured_slots` (unique vibe+placement+product), `faqs`, `policies` (slug unique, `version`, `published`), `policy_versions` (history, unique policy+version).

## Operations (`ops.ts`)
`settings` (key PK, jsonb `value`, `is_placeholder`, `updated_by`), `contact_messages`, `support_cases` (`photo_paths text[]`), `notification_outbox` (indexed by `status`, `next_attempt_at`), `admin_audit_log`, `rate_limits` (PK `key`, `window_start`).

## Analytics (`analytics.ts`)
`analytics_events` (indexes (`event`, `ts`), (`product_id`, `ts`), session, `ts`; `product_id` is intentionally not an FK), `product_engagement_daily` (unique (`date`, `product_id`)).

## Reference (`reference.ts`)
`states` (`code` char(2) = GST state code, `name` unique, `iso`, `type` state/ut, `zone`), `pincodes` (`pincode` char(6) with a digits-only CHECK, `district`, `state_code` FK, `zone`, `serviceable`, `cod_allowed`). Loaded by `pnpm db:import-reference` from `data/reference/`; re-imports refresh names/districts/zones but never overwrite `serviceable` or `cod_allowed`.

## Auth (`auth.ts`, Better Auth)
`user` (adds `role` NOT NULL default `customer`, `banned*`, `two_factor_enabled`), `session`, `account`, `verification`, `two_factor`. Regenerate after changing Better Auth plugins:
```
pnpm dlx auth@latest generate --config <file exporting betterAuth({...same plugins})> --output /tmp/auth-schema.ts -y
```
then merge the diff into `auth.ts` (keep `withTimezone: true` and the `role` default) and run `pnpm db:generate`. (The CLI cannot load `src/server/auth/auth.ts` directly because of `server-only`; use a throwaway config without it.)

## Order / payment / fulfilment axes
Three independent enums on `orders`; allowed transitions live in application code (`orders/state.ts`, Phase 4).

| Axis | Values |
|---|---|
| `order_status` | `pending_payment` -> `confirmed` -> `processing` -> `completed`; branches `cancelled`, `expired` |
| `payment_status` | `unpaid`, `paid`, `failed`, `cod_pending`, `cod_collected`, `partially_refunded`, `refunded` |
| `fulfillment_status` | `unfulfilled` -> `packed` -> `shipped` -> `out_for_delivery` -> `delivered`; branches `rto`, `returned` |

Related enums: `payment_method` (razorpay, cod), `payment_row_status` (created, authorized, captured, failed), `refund_status` (pending, processed, failed, manual), `reservation_status` (active, converted, released), `movement_reason` (sale, restock, adjust, cancel_restock, return_restock, correction), `redemption_status`, `coupon_kind`, `product_status`, `image_kind`, `invoice_kind`, `banner_placement`, `featured_placement`, `faq_category`, `contact_status`, `support_type`, `support_status`, `support_resolution`, `notification_channel`, `notification_status`, `state_type`.

## Settings
`src/server/services/settings-registry.ts` defines every key (Zod schema, group, label, placeholder, `requiredForLaunch`, `locked`/`confirmed`). `settings.ts` reads/writes them (`getSetting`, `getSettings`, `setSetting`, `getLaunchBlockers`, `seedMissingSettings`). Rows hold `{ value, is_placeholder }`; `setSetting` validates, clears the flag and writes an `admin_audit_log` row in the same transaction. Locked keys (`prices_include_gst`, `backorders`) cannot be changed.

## Auth and RBAC
`src/server/auth/permissions.ts` is the permission matrix (`can(role, "order:refund")`, `assertCan`); the same matrix builds Better Auth's access control for the admin plugin. Roles: `owner`, `admin`, `fulfilment`, `customer` (default).

Caveat for Phase 3: Better Auth's two-factor after-hook only intercepts credential sign-ins (`/sign-in/email`, `/username`, `/phone-number`), not `/sign-in/email-otp`. The admin gate must therefore enforce TOTP itself for admin roles on the OTP flow (e.g. require `user.twoFactorEnabled` and a verified second step before issuing admin access), or admins must use a credential sign-in that triggers the plugin's challenge.

## Testing
`pnpm test` runs unit tests only. `pnpm test:integration` (needs `supabase start`) drops and recreates `ifonli_test`, applies all migrations, and truncates every table before each test.
