## Auth decision (2026-10-30, plan-resolved/reversible)

| ID | Decision | Resolution |
|---|---|---|
| D-AUTH-1 | Mandatory admin TOTP vs email-OTP login | Better Auth's twoFactor hook does not fire on `/sign-in/email-otp`. **Admins (owner/admin/fulfilment) sign in with email + password + TOTP** (native Better Auth credential flow with 2FA); **customers use passwordless email OTP**. Phase 3 admin gate additionally checks `twoFactorEnabled` and forces TOTP enrolment on first admin login. |

## Customer accounts, order actions and DPDP (Phase 5, 2026-10-31, plan-resolved/reversible)

| ID | Decision | Resolution |
|---|---|---|
| D-ACC-1 | Admin sessions in the customer area | An admin-role session (owner/admin/fulfilment) is not a customer. `requireCustomer()` sends it to /admin (or throws `ForbiddenError` in Server Actions); OTP login is refused for admin addresses and the login screen never reveals which addresses are staff. |
| D-ACC-2 | Which orders an account sees | Orders with `user_id` = the account, plus orders whose e-mail equals the account's VERIFIED e-mail (guest orders placed before signing up). An unverified e-mail grants nothing by address. Expired (never paid) checkouts are left out of the history. |
| D-ACC-3 | Customer cancel | Allowed while the fulfilment status is in `cancellable_statuses`, but never past `packed` whatever the setting says (a shipped parcel cannot be recalled). Prepaid: automatic full refund; COD: cancel only. Same transaction as the admin cancel (`cancelOrderCore`). Idempotent; rate limited by IP and order. |
| D-ACC-4 | Claim window for "Report a problem" | `damaged_claim_window_hours` never blocks a report (statutory rights for defective/damaged/wrong goods). A report after the window is accepted, flagged in the case notes and the team alert ("[Late report]"), and the customer is told kindly. A placeholder (unset) window flags nothing. Goods problems are offered once the parcel is shipped; "Something else" any time the order is live. |
| D-ACC-5 | Support photos | Up to 4 JPEG/PNG/WebP, 8 MB each, uploaded straight to the private bucket with signed upload URLs (the order must be owned; rate limited); the case only stores paths of files that really exist with an image type and size. Without Supabase Storage configured the picker is hidden and the report still works. EXIF is not stripped (the bucket is private and only staff read it). |
| D-ACC-6 | Wishlist sync | First sign-in from a device: union of device and account lists (earliest save time wins), pushed back. Afterwards the account is the source of truth and the device follows it, so a removal on another device sticks. Sign-out clears the device copy. A non-personal hint cookie (`ifonli_acct`) tells the browser whether to run the sync; the Server Actions re-check the real session. |
| D-DPDP-1 | Account deletion and retention | Deleted: login (user, sessions, accounts), profile, saved addresses, wishlist, open carts, pending sign-in codes. Kept: orders, lines, events, shipments, invoices and refunds, with the name/address/e-mail/phone typed at checkout (tax and accounting records, consumer-protection evidence); `orders.user_id` becomes NULL so they belong to no account. Support cases and their photos stay with their order. Contact-form messages are not touched. An audit row (`customer.delete`) records counts only, never the e-mail. A person who signs up again with the same e-mail sees those orders again (they match by verified e-mail). Export (`/api/account/export`) covers profile, addresses, orders, visible timeline, shipments, wishlist, support cases (no staff notes) and contact messages. |
